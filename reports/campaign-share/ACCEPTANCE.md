# 验收步骤与本次证据边界

自动化命令（在仓库根目录，不连接生产）：

```bash
php isolated/campaign-share/tests/run.php
php isolated/campaign-share/scripts/hash-guard.php
php isolated/campaign-share/scripts/rollback.php --policy
```

本次 `php isolated/campaign-share/tests/run.php` 结果：19 项全部通过，进程退出码 0。覆盖范围是测试进程内的 HTTP 处理、本机 `php -S` 默认关闭入口，以及两个进程对同一 SQLite 文件的并发领取。输出见 `evidence/TEST_RUN.txt`。

已在该测试进程中执行并观察到的行为：

- 默认关闭时，新路由和原入口路径都是 404，空库也不会被查询。
- 网页入口即使把配置改成开启，仍然 404，且不发会话 cookie。
- 失败闭合验证器在证明材料正确时也不发钥；已有旧钥和没有旧钥的失败响应正文相同。
- 格式校验失败不会调用验证器，也不会回显号码。
- 缺少 CSRF、来源站点不对、超过频率上限时不写挑战；频率提示不带号码。
- 领取前的本人查询不发钥。请求体中的他人号码和推广者编号不改变会话号码和归属。
- 同号第二次领取返回原密钥，名额不增加。
- 跨推广者、跨期次不新发、不改归属。注入的手工旧钥只读返回，不进入新池。
- 名额耗尽只拒绝新号；已有会话仍能取回原钥。
- 停期拒绝新领，已有钥仍返回；停期的受信进站信号不写「已使用」。页面文案写明不能保证关闭期进站和使用统计。
- 「去使用」返回带风险标记的 `?key=` 预填地址，不改状态。不存在客户端自报已使用的路由。
- 推广者列表、详情、搜索、CSV 和 HTML 不包含完整号、掩码或完整密钥；用他人会话、序号或手机号取号失败，且失败正文不回显号码。
- 领取事务在提交前失败会回滚密钥和名额，响应不带异常文本。
- 同号并发只产生一把密钥；名额为 1 时两个不同号码只有一个成功。
- SQLite down 会删掉已领密钥；`rollback.php --apply` 不会。脚本拒绝数据库参数和不安全路径。
- README 哈希仍是 `64b9ebb9b196612b9ad93859faa24385`。两个红线路径在仓库中缺失。

介绍页截图只证明结构和文案，不是视觉验收：

- `evidence/share-desktop.png`、`evidence/share-mobile.png`、`evidence/share-closed.png` 来自本机回环上的夹具服务。该服务使用失败闭合验证器，不能发钥。
- `evidence/share-dialog.png` 用同一模板把对话框设为打开后截取，用来看见表单结构。无头浏览器没有完成点击。

## 还不能当作生产验收的部分

- 没有现网 PHP、数据库和管理员登录，推广者会话只在测试里签发，没有接到现网后台。
- 旧手工钥通过内存目录注入验证，没有读取现网密钥表。
- 「已使用」没有接到 `verify.php`。不改红线就无法在真实进站时写状态。
- MySQL 脚本没有在 MySQL 上执行。
- 持号验证没有可复用的现网实现，也没有新增短信供应商。生产验证器保持失败闭合。
- Refero 不可用，仓库没有设计系统，所以没有视觉稿。
- 没有真实支付、真实短信、真实进站或生产回归。普通首页、购钥、支付和奖励路径在本仓库中不存在，测试证明的是本仓库原有 README 未被修改，以及新入口默认关闭。
